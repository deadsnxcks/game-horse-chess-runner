# Правила для AI-агента

Этот проект — учебная работа студента. Помогай писать код, но не забирай у студента контроль над проектом.

## Главное правило

**Делай минимальное изменение, которое решает поставленную задачу.**

Не переписывай проект целиком без прямого запроса.

## Перед изменением

1. Кратко сформулируй, что собираешься изменить.
2. Укажи файлы, которые потребуется тронуть.
3. Если задача неоднозначна, выбери самое простое решение, соответствующее текущей архитектуре.

## Во время изменения

- сохраняй TypeScript strict;
- не добавляй библиотеку, если задачу легко решить без неё;
- не создавай новые уровни абстракции "на будущее";
- не меняй несвязанные файлы;
- выноси важные игровые параметры в понятные константы;
- предпочитай маленькие функции;
- не удаляй рабочую механику без явного требования;
- не добавляй backend, базу данных или сетевую часть без явной необходимости.

## После изменения

Сообщи:

1. какие файлы изменены;
2. что именно изменилось;
3. как проверить результат вручную;
4. какие риски или ограничения остались.

Если возможно, предложи выполнить:

```bash
npm run typecheck
npm run build
```

## Запрещено

- генерировать полностью новую игру вместо изменения существующей;
- молча менять архитектуру всего проекта;
- прятать важную игровую логику в магических числах;
- добавлять платные сервисы;
- добавлять зависимость только ради нескольких строк кода.

## Контекст курса

Проект должен оставаться:

- индивидуальным;
- браузерным;
- небольшим;
- запускаемым на слабом компьютере;
- пригодным для последующей публикации и сбора игровых метрик.

## Команды проекта

- `npm run dev` — локальная разработка;
- `npm run typecheck` — проверка типов;
- `npm run build` — типчек + прод-сборка в `dist/`;
- `npm run preview` — запуск собранной игры на `http://localhost:4173/`.

## Проверки перед словом «готово»

1. `npm run typecheck` — без ошибок.
2. `npm run build` — без ошибок.
3. Собранная игра открывается через `npm run preview`, а не только через dev-сервер.
4. Если менялось то, что видит или чувствует игрок (ходы, взятия, фазы, смерть, рестарт, счёт и рекорд, звук, пауза, мобильный вид), — пройден смоук из `.opencode/skills/horsechess-smoke/SKILL.md`.

Отчёт без команды и кода возврата считается непроверенным. «Должно работать» — не результат.

## Смоук-чеклист (руками, полминуты)

- ход конём только буквой «Г», подсветка точек верная;
- взятие начисляет ценность фигуры и останавливает экран в фазе «Охота»;
- смерть от фигуры и от красной полосы срабатывает, экран проигрыша объясняет причину;
- «Ещё раз» начинает новую игру с фазы 1;
- рекорд сохраняется после перезагрузки вкладки;
- сворачивание вкладки ставит на паузу, возврат продолжает;
- звук выключается и включается на паузе;
- на вьюпорте 390×844 ничего не уезжает и не обрезается.

## Правила для агентов

- Одна задача — одно изменение. Не смешивать рефакторинг с фиксом.
- Не добавлять зависимости без явного разрешения. Не трогать `dist/`, `node_modules/`, `package-lock.json`.
- Запрещено: `git push`, `git reset --hard`, `git clean`, `rm -rf`. Коммит делает студент сам.
- Не утверждать «работает», если проверка не запускалась. Не проверял — писать «не проверено» и почему.
- В отчёте о правке: что изменилось, как проверить руками, что осталось рискованным.
- Не переписывать сцены и не менять архитектуру без прямой просьбы.
